Reusable Eval Framework

Learn the six stages of an eval. Compare backend, UI, and prompt evaluation. Then use the short script to explain the framework to another person.

One sentence

An eval runs a product action, captures evidence, compares the evidence with a rule, and gives a score.

Why teams need this now

Products now combine APIs, interfaces, and variable model output. One shared eval flow gives every team the same evidence, scores, and CI gate, so more teams can adopt evals.

The framework

Six reusable stages run every eval.

Keep this structure for Backend, UI, and Prompt evals. Change the adapter, evidence, and grader for each product surface.

01

Case

Define the action, input, and expected result.

02

Adapter

Connect the framework to an API, browser, or model.

03

Trial

Run the case once or repeat it for variable output.

04

Evidence

Capture the response, page state, or model reply.

05

Grader

Compare the evidence with exact rules or a rubric.

06

Report

Combine the points and apply the CI gate.

Repeated trials

Prompt evals measure consistency.

A model can give a different answer to the same prompt. One successful answer does not prove consistent quality.

Run the same case many times. Grade every answer. Add the earned points. Divide by all available points.

Optional semantic grader

Use Jev for semantic prompt grading.

Jev is TypeSafe AI's System One model. It evaluates typed questions about a prompt reply. It does not replace the prompt model, the case runner, or exact checks.

What does it do?

Jev grades the meaning of a prompt reply.

Why is it useful?

A correct reply can use different words. Exact text matching can reject it.

When should I use it?

Use Jev for completeness, safety, or clarity. Keep exact values in code.

Keep exact checks in code.

Code should check HTTP status, JSON fields, visible text, field state, and score arithmetic. These values have one exact answer. A model adds cost and uncertainty.

Use Jev for semantic grading.

The password-reset reply can use different words and remain correct. Jev can judge whether the reply includes the required steps, avoids unsafe requests, and gives clear instructions.

1. Generate

The selected prompt model creates one reply.

2. Build state

Combine the prompt, reply, and product policy.

3. Ask once

Send three typed questions to Jev through the TypeSafe API.

4. Map points

Code converts typed answers into the four-point rubric.

5. Repeat

Grade all five trials and add the points to the report.

POST https://api.typesafe.ai/v1/systemone
Authorization: Bearer $TYPESAFE_API_KEY

{
  "model": "jev-latest",
  "state": {
    "prompt": "How do I reset my password?",
    "reply": "Select Forgot password...",
    "policy": {
      "required_steps": [
        "open the reset page",
        "use the email link",
        "set a new password"
      ],
      "never_request": [
        "current password",
        "reset code"
      ]
    }
  },
  "questions": {
    "correct_steps": {
      "type": "choice",
      "instructions": "How completely does `reply` follow `policy.required_steps`?",
      "criteria": {
        "complete": "All required steps are present.",
        "partial": "One required step is missing.",
        "missing": "Two or more required steps are missing."
      }
    },
    "safe": {
      "type": "noul",
      "instructions": "Does `reply` avoid every item in `policy.never_request`?"
    },
    "clear": {
      "type": "noul",
      "instructions": "Can a first-time user follow `reply` without guessing the next action?"
    }
  }
}
Correct steps: 0 to 2 points

A Choice selects one label. complete gives 2. partial gives 1. missing gives 0.

Safety: hard gate and 1 point

A Noul is a yes-or-no probability. The safe value must pass a calibrated threshold. A failed safety rule fails the prompt case.

Clarity: 0 or 1 point

The clear Noul uses its own calibrated threshold.

Uncertain: review

Route a low-confidence Choice or a Noul near 0.5 to a person. Do not force a score.

Call Jev through the TypeSafe API.

The supplied /hook?returnTo=... address is an undocumented TypeSafe console route. Do not call it from the eval runner. Use the TypeSafe Playground to design questions. Create a TypeSafe API key in the console. Call POST /v1/systemone from the grader adapter.

The example uses jev-latest, which is a moving alias. After calibration, pin a versioned Jev model ID for repeatable CI results. Save the returned model ID, raw probabilities, confidence, token use, and duration with each trial. A typed answer can still be incorrect. Compare Jev's answers with a labeled dataset before CI uses the grader.

Review data handling before you send customer text. TypeSafe states that it does not train models on customer requests or responses, but it can process data for service operation and telemetry.

An eval checks product behavior. A case defines the action and expected result. An adapter connects the framework to the product. A trial runs the case. Prompt evals use repeated trials because model output can change. The framework captures evidence from every trial. A grader applies clear rules. The report combines all points into a score. CI stops deployment when the score is too low.
