Start here

Reusable evals, explained simply.

Learn the five parts of an eval. See how the same framework checks a backend and a UI. Then use the short script to explain it to another person.

One sentence

An eval runs a product action, captures evidence, compares the evidence with a rule, and gives a score.

The model

Every eval uses the same flow.

The product can change. The flow does not change. This makes the framework reusable.

01

Case

Describes the action and the expected result.

02

Adapter

Performs the action in the backend or UI.

03

Evidence

Records what the product returned or displayed.

04

Grader

Compares the evidence with a clear rule.

05

Report

Shows each result, the final score, and the gate.

Two examples

One framework checks two product surfaces.

Only the adapter changes. The case, evidence, grading, score, and report use the same model.

Backend eval

Create a task through the API

  • CaseCreate a task named Publish guide.
  • AdapterSend POST /api/tasks.
  • EvidenceStatus is 201. The response contains the title.
  • RuleStatus equals 201. Title equals the input.
  • ResultBoth rules pass. The case earns all available points.
UI eval

Create a task through the page

  • CaseCreate a visible task named Publish guide.
  • AdapterFill the title and select Add task.
  • EvidenceThe task list contains the new title.
  • RuleVisible text includes Publish guide.
  • ResultThe rule passes. The case earns all available points.
1.00

Final score

Read the result

A score is a weighted pass rate.

21 earned ÷ 21 available = 1.00

The example gate is 0.90. The score is 1.00, so the eval passes. CI stops the deployment when the score is lower than the gate.

Teach it back

Explain evals in 30 seconds.

Select the button. Read the script aloud. If you can explain each sentence, you understand the model.

An eval checks product behavior. A case tells the product what to do. An adapter performs the action. The adapter captures evidence. A grader compares the evidence with a rule. Each rule has a weight. The report combines the weights into a score. CI stops deployment when the score is too low.
